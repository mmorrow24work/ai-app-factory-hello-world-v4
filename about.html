About this build

ai-app-factory-hello-world-v4 is a disposable test site: it exists to exercise the ai-app-factory unattended build pipeline, not to be a product. If you've never seen this repo before, here is the full path a change takes from request to a live page.

  1. Intake issue. The requester files an issue in the ai-app-factory meta-repo asking for a project like this one.
  2. Design doc PR. A design doc is drafted and merged, laying out what gets built, in what order, and which lane (attended or unattended) each piece runs in.
  3. Provisioning. The repo is bootstrapped from the ai-app-factory template. Two steps here are human-only: adding pages-deploy.yml by hand (the pipeline's token doesn't carry Workflows scope, so it can't create or edit workflow files), and turning on GitHub Pages for the repo in its Settings.
  4. Milestone seeding. Milestone issues (M0 through M3, this page is M3) are filed in this repo, each one sequenced so it doesn't start until the milestone before it has merged.
  5. Unattended implementation. Applying the claude-go label to an issue fires .github/workflows/claude.yml, which hands that issue to Claude Code running unattended. It implements the issue's acceptance criteria and opens a pull request.
  6. Requester review. The requester reviews and approves the pull request from their own account.
  7. Merge. That approval is what review-decision.yml's requester-match branch checks for before merging the pull request to main.
  8. Deploy. The merge to main triggers pages-deploy.yml, which publishes the repo root straight to GitHub Pages — no build step, no bundler, nothing to compile.

Split by who can do it: the requester, @mmorrow2012, is the one human step inside the repeatable loop — approving each pull request from their own account, which is what authorizes the merge. The owner, @mmorrow24work, did the two steps that only happen once and can't be done unattended at all: adding pages-deploy.yml and enabling Pages. Everything else — reading the issue, writing the code, opening the PR — is Claude Code running unattended.

This project ran alongside ai-app-factory-hello-world-v3, deliberately. v4 is near-identical to v3 by design: the content of either site isn't the thing under test, concurrency is. Running two unattended builds at once, with the same requester and the same Claude Code subscription token, is what actually exercises the pipeline — whether two projects can move through intake, implementation, review, and deploy in parallel without stepping on each other.
